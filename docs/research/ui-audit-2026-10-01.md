# UI/UX audit — 2026-10-01

**Why:** Victor: the app "looks like something from a rough video tutorial, not a production app";
colours don't pop or complement; wants Discord/Telegram-grade depth (he called it neumorphism),
and designed toasts, buttons, loading/pending states, transitions and animation. Illustrations at
most, no other assets. This is the evidence base for the new direction; it decides nothing.

Tags: 🟢 fact (named source) · 🔵 observed (device or code) · 🟣 synthesis · 🟡 hypothesis.

## 1. What the app is today (🔵, Infinix HOT 60i + code)

**Look**
- One flat navy ground (`#151A2E`) with outlined boxes of almost the same tone (`#1E2438`,
  border `#2A3149`). Surfaces barely separate; nothing has depth, so nothing leads the eye.
- Gold is used for every emphasis at once (CTA, step icons, nav, labels) and is a muted
  ochre (`#C9A227`) on navy, so it reads dull rather than precious. Slate secondary text is low.
- Corners 3–6 px everywhere, a Material 2-era form style; inputs and chips look default.
- Large dead areas: Profile uses the top third; Jobs/Applications are a single centred line.
- No screen headers on the tabs (no title, no context, no count).

**Feel** (counts across `lib/`)
- 0 page transitions or shared-element animations (23 stock `MaterialPageRoute`s).
- 0 `AnimatedSwitcher`/`AnimatedContainer`: every state change is an instant swap.
- 0 haptics, 0 skeletons, 0 dialogs. 28 bare `CircularProgressIndicator`s, 17 stock SnackBars.
- Buttons have no pressed/loading/success states beyond the Material default.

**Defects found while looking**
1. **Sign out doesn't leave the app.** After an in-session login, `LoginScreen`/
   `VerifyEmailScreen` *push* `AppShell` over the root router, so logout updates the root
   underneath and the user stays on Profile as "Unnamed" with a "?" avatar. Sign out also has no
   confirmation. (Reproduced on the device.)
2. **Profile checklist connectors** render as full-width grey bars, not thin lines between the
   step icons.
3. **Applications tab** is labelled "Applications" but its empty state says "No active contracts".
4. **Keyboard covers Save** on Build your profile (button sits in the scroll, not anchored).
5. Skill chips don't show a selected state clearly; no preview of what a client will see.

## 2. What the references actually do

**Pendu (this workspace's own, owner-approved)** — `pendu-mobile/docs/core/UI_PLAYBOOK.md` and
the three prototypes (`prototypes/party-create-flow.html`, `onboarding-flow.html`,
`esports-tournament-flow.html`). 🔵
- Process: audit → research → **HTML prototype with the app's real tokens and real data** →
  on-device spike for risky techniques (budget phone) → build spec → build → device round.
- A token sheet first (ground, 3–4 surface steps, hairline `rgba(255,255,255,.08)`, radii
  10/14/20/28/999, one accent per screen + brand primary, motion tokens).
- Components: glass card (translucent fill + top highlight + hairline), segmented control with a
  sliding thumb, choice tiles (both options visible, radio semantics), detail rows + bottom
  sheets, pill chips, sticky CTA bar, stepper, toasts (top, pill, icon + colour by kind, ~2.6 s),
  a live preview of the result while you fill a form.
- Motion: 250 ms state / 400 ms layout / 450–700 ms arrivals; `easeOutBack` for selection pops,
  `easeOutCubic` otherwise; press-scale 0.92–0.97 on every tappable; haptic on choices, stronger
  on the payoff; staggered entrance; **waiting is a designed state, not a spinner**, held ≥1.2 s
  so it never flashes; reduced-motion respected; sound on success (optional).
- Honest data only: every label backed by a real field; no UI without its backend.

**Discord** (🟢 token write-ups of the shipped app; several sources agree 🟣)
- Depth by **tonal layering**: 4 stacked dark tones (`#111214` floating · `#1e1f22` deepest ·
  `#2b2d31` panels · `#313338` content), not borders. Shadows only on floating things
  (`0 8px 16px rgba(0,0,0,.24)`). One saturated accent (Blurple `#5865F2`) used sparingly so it
  pops. Generous rounded geometry; off-white text (never pure white); micro-animations on every
  state change.

**Telegram** (🟢 60fps.design catalogue; Telegram iOS internals write-ups)
- Bottom sheets, elastic pull, swipe gestures, a copy-link toast, spring transitions
  (`0.4 s, .spring` on state changes), skeleton while a chat loads, blurred glass input bar,
  send animations. The polish is motion and responsiveness, not ornament.

**Neumorphism** (🟢 Axess Lab; socialanimal.dev 2026; UX StackExchange)
- Soft dual shadows on a monochrome ground; boundaries made only of shadow typically reach
  1.3–1.8:1 contrast vs the 3:1 WCAG 1.4.11 minimum for controls. In dark mode the light
  shadow reads as a rendering artifact. Recommended at most as a "spice" on non-interactive
  surfaces, never on CTAs, inputs or navigation. One A/B test: flat CTA +23% click-through.
- 🟣 **Discord and Telegram are not neumorphic.** What Victor is pointing at is tonal depth +
  rounded soft geometry + motion. That is achievable and accessible; true neumorphism is not.

**States and feedback** (🟢 Material 3, Apple HIG; UI/UX Atlas)
- No indicator under 200 ms; loading indicator 200 ms–5 s; progress indicator over 5 s.
- Skeletons for predictable lists; spinners only inside the button or a small region.
- Toast/snackbar: low priority, one at a time, 4–10 s, Undo for reversible actions, never the
  only place information appears. Dialogs only for decisions that must block.
- Empty states answer: why it's empty, what to do next, what it looks like when full.
- Errors: inline next to the cause, specific, with Retry; keep the user's input.
- Hold a loading state ≥300–500 ms so it doesn't flicker.

## 3. Conflicts with the current brand rules (CLAUDE.md "Brand — v0")

v0 bans gradients, glows, heavy shadows and blur, and caps radii at 3–6 px. The direction above
needs at least: radii up to ~20–28 px (and pills), soft shadows on floating layers, and possibly
a faint top highlight on cards. v0 says it is "not locked". Changing it is Victor's decision and
must be written back into CLAUDE.md, so later sessions don't enforce the old bans.
